## Live failures (2/12), one cause
`get_valid_filename__rettype` and `normalize_newlines__rettype` both use `@keep_lazy_text`. A's patch moves the decorator onto `_<f>_impl` and adds an undecorated wrapper that returns `_CoordT(...)`. That changes `sigHash` (decorators included), so the change is classed as `contract`. The signature *text* is identical, though, so the notice read `before: def f(name)` / `after: def f(name)` and showed neither the body nor the new class. B could not see the return type change.

Fix (after the gate, tuned on this held-out set, so it does not change the number above):
- When the sig text is unchanged, a contract notice shows the body change.
- `related` (new symbols referenced) is computed for contract changes as well as behavior.
- Docstrings are stripped from notice snippets, and `+` lines get first claim on the 6-line budget.
