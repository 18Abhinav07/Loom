# Loom B4–B7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (native, Sonnet). Steps use `- [ ]`.
> Tests stay short: one `it` per behaviour, no snapshot dumps, no docs beyond what a task names.

**Goal:** Teams of any size run from the daemon (lead tool, dashboard, CLI). Two people collaborate through git with deterministic collision records. Every view has a real route. The UI is a clean product: a Home, a Lead chat, team, people, collisions and a Bench with StaleBench numbers.

**Architecture:** The team machinery in `cli/src/run2.ts` moves into `daemon/src/team/`. A `Team` owns one worktree and one open-stdin `claude` per task, honours `after`, and reuses `LiveRoutes` (`addRun/addAgent/land/take`) for locks, landing and notices. Collisions are written as `collision` events into `.loom/sessions/<teamSid>.coord.jsonl` with `collisionId`, so imports dedupe. Read routes are Cypher queries in one `daemon/src/views.ts`. The dashboard fetches only those routes.

**Tech Stack:** TypeScript, Node, FalkorDB, vitest, React + Vite (`apps/dashboard`), Python bench (`bench/e5`).

**Spec:** `docs/superpowers/specs/2026-10-16-loom-product-design.md` §3.4, §3.6, §4.3, §5, §7, §8 (B4–B7), §11.

## Global Constraints
- Agents and every spawned `claude` use `subscriptionEnv(process.env)` from `@loom/core`. Never a paid key.
- Tests never spawn real `claude`. They use `test/fake-claude.mjs` (Task 1). Real runs need the user's go-ahead. CLI test runs use `--model haiku` or `sonnet` only.
- **Any number of agents:** a team has one agent per plan task. There is no cap in code. `maxParallel` defaults to `tasks.length`.
- Session file per writer: `.loom/sessions/<sid>.<writer>.jsonl`. The team coord file is writer `coord`. Agent writer = task id.
- Collision kinds are exactly: `lock_wait`, `lock_denied`, `caller_warning`, `stale_version`, `merge_conflict`, `landing_rejected`, `divergence`, `out_of_scope`.
- `outcome` is exactly one of: `waited`, `adapted`, `acked`, `resolved`, `rejected`, `open`.
- Event id of a collision = `collisionId(kind, parties, region, version)`.
- An agent session event carries `kind:'agent'`, `parent: <lead sid>`, `team`, `plan`, `task`, and `person` = the lead's person.
- UI copy never says "Django". Say "a real open-source Python codebase". Bench and demo views show no cost and no time.
- Daemon guard: every new route goes through `localOnly` (`daemon/src/guard.ts`), as existing routes do.
- PREREG: no counted bench run on this build without the addendum from Task 6 and the user's go-ahead.
- Branch `feat/b4-team` off `feat/b3-lead`. Use `feat/b5-collab` for Tasks 7–9 and `feat/b7-ui` for Tasks 10–14. Stack them, one PR each. The user merges.
- Suite: `pnpm -r build && npx vitest run` from the repo root. Log to the scratchpad and read the tail.

## Review Focus
1. **Agent dies mid-task** (crash or usage limit). The team marks it `failed` and still starts the tasks that don't depend on it. Dependants stay `blocked`; they never hang. Test in Task 2.
2. **Message to a finished or stopped agent.** Returns `{ok:false, error:'agent <a> is not running'}`; it does not throw or write to a closed stdin. Test in Task 4.
3. **Two teams in one repo at once.** Their worktrees, branches and coord files don't collide: names are keyed by team id. Test in Task 2.
4. **Sync run twice, or on both machines.** The same divergence is one record, not two. Test in Task 7.
5. **Empty data** (fresh repo, no teams, no collisions). Every route returns `[]` or `{}`, not a 500. Every screen shows an empty state. Tests in Tasks 8 and 10.

### Task 1: Open-stdin agent process

**Files:** Create `packages/daemon/src/team/agent.ts`, `packages/daemon/test/fake-claude.mjs`. Test: `packages/daemon/test/team-agent.test.ts`.

**Interfaces — Produces:**
```ts
export type AgentState = 'pending'|'running'|'idle'|'landed'|'failed'|'stopped'|'blocked';
export interface AgentOpts { id: string; cwd: string; prompt: string; env: NodeJS.ProcessEnv; model?: string; allowed: string[];
  traceFile: string; bin?: string /* default 'claude'; tests pass fake-claude.mjs */ }
export class AgentProc extends EventEmitter {   // events: 'reply'(text) 'result'({ok, sessionId}) 'exit'(code)
  constructor(o: AgentOpts); start(): void; send(text: string): boolean /* false if not running */;
  stop(): void; get sessionId(): string|undefined; get running(): boolean;
}
export function userLine(text: string): string // JSON line {type:'user',message:{role:'user',content:[{type:'text',text}]}}+'\n'
```
Argv: `-p --input-format stream-json --output-format stream-json --verbose --allowedTools <allowed> [--model m]`. The prompt is the first `userLine`, written to stdin; stdin is never closed until `stop()`. Every stdout line is appended to `traceFile`. A `type:'assistant'` text emits `reply`. A `type:'result'` emits `result`. The env comes in already wrapped in `subscriptionEnv`.

`fake-claude.mjs`: reads stdin lines. For each user line it prints an `assistant` echo, `"ack:<text>"`, then a `result` line `{type:'result',session_id:'fake-<pid>',is_error:false}`. If the text contains `CRASH`, it exits 3. When `FAKE_COMMIT=1`, it writes `fake-<n>.txt`, then runs `git add` and `git commit` in its cwd.

- [ ] Test `stop ends the process; send after stop returns false`.
- [ ] Test `crash emits exit with nonzero code`.

### Task 2: Team scheduler (N agents, `after`, failure isolation)

**Files:** Create `packages/daemon/src/team/team.ts`. Modify `packages/daemon/src/live/routes.ts` only if `addRun` needs a team id. Test: `packages/daemon/test/team.test.ts`.

**Interfaces — Consumes:** `AgentProc`; `TeamPlan`/`parseTeamPlan` (`@loom/planner`); `LiveRoutes.addRun/addAgent/land/take`; `appendEvent`, `ulid` (`@loom/memory`); `SUFFIX`, `allowedTools`, `MAX_RESUMES`, `usageLimited`. Move the last four into `daemon/src/team/prompt.ts` and re-export them from cli, so cli keeps compiling.

**Produces:**
```ts
export interface TeamAgentView { id: string; title: string; state: AgentState; after: string[]; sid: string; worktree: string;
  branch: string; lands: string[]; resumed: number; lastReply?: string }
export interface TeamView { id: string; plan: string; goal: string; repo: string; leadSid: string|null; person: string;
  landed: string; state: 'running'|'done'|'stopped'; agents: TeamAgentView[]; startedAt: number }
export interface TeamDeps { routes: LiveRoutes; bin?: string; onAgentEvent?(team: string, agent: string, text: string): void }
export class Team {
  static async start(d: TeamDeps, o: { repo: string; planPath: string; leadSid?: string|null; person: string; model?: string;
    maxParallel?: number }): Promise<Team>;
  view(): TeamView; message(agent: string, text: string): {ok: boolean; error?: string};
  stopAgent(agent: string): {ok: boolean; error?: string};
  restartAgent(agent: string, note?: string): Promise<{ok: boolean; error?: string}>;
  stop(): Promise<void>; merge(into: string): Promise<{ok: boolean; error?: string; commit?: string}>; done(): Promise<TeamView>;
}
```
**Rules** (port from `runPlan2`; the team id replaces run8):
- Use `id = ulid()`.
- Worktree: `.loom/wt/<id8>/<task>`. Branch: `loom/<id8>/<task>`. Landed branch: `loom/<id8>/landed`.
- Trace: `.git/loom/runs/<id8>/<task>.jsonl`.
- A task starts when every `after` task is `landed`.
- A task whose `after` contains a `failed` or `stopped` task becomes `blocked`.
- On `result`: call `land`. A `landed` outcome sets the task to `landed`. A rejection is retried, up to `MAX_RESUMES` times, through `send()` with the `take()` notices; it is not a respawn.
- Events, via `appendEvent(repo, teamSid, 'coord', …)`:
  - `team` with action `started`, `agent_started`, `agent_landed`, `agent_rejected`, `stopped` or `merged`.
  - Per agent, `appendEvent(repo, agentSid, taskId, {type:'session', kind:'agent', parent: leadSid, team: id, plan: slug, task, person})`.
- `onAgentEvent` fires for every reply, landing and rejection.

- [ ] Tests (fake-claude with `FAKE_COMMIT=1`, temp git repo, the real `LiveRoutes` against the test FalkorDB as existing live tests do):
  - `runs a 1-task plan to landed`.
  - `runs 3 independent tasks in parallel`.
  - `runs 5 tasks; c after a,b starts only after both land`. Assert order from the coord `team` events.
  - `crashed agent → failed, dependant blocked, independent still lands` (Review Focus 1).
  - `two teams in one repo use disjoint worktrees, branches and coord files` (RF3).
  - `agent session events name parent lead, team, plan, task and person`.

  version?: string|null; waited_ms?: number; detail: string }
export function writeCollision(repo: string, teamSid: string, c: CollisionIn): string /* returns id; appends to coord file */

`LiveRoutes` gains `onCollision?: (run: string, c: CollisionIn) => void`. `Team` wires it to `writeCollision`.

Mapping:
| Source | Collision | outcome |
|---|---|---|
| Lease or hook deny | `lock_denied` | `rejected` |
| Gate wait, then wake | `lock_wait` with `waited_ms` | `waited` |
| `contract_use` / `new_caller` notice | `caller_warning` | `open` |
| Land result `contract_break` or `tests_failed` | `landing_rejected` | `rejected` |
| Land result `conflict` | `merge_conflict` | `rejected` |
| Out-of-scope write | `out_of_scope` | `open` |
